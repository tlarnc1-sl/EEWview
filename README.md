# EEWview

日本の地震情報をリアルタイムに1画面で眺めるための、個人用ブラウザアプリ。公開しない。

**防災アプリではない。** 命を守る役割は特務機関NERV防災アプリなど許可事業者のサービスが担う。
これは「今この瞬間、日本のどこで何が起きているか」を眺めるための計器盤。

## 動かす

```sh
npm install
npm run dev      # 既定は本番（Wolfx + P2P本番）
npm test         # Vitest（143件）
npm run build    # dist/ に静的ファイル
```

接続先は `.env.local`（`.env.example` を参照）。
実装を試すときだけ `VITE_P2P_ENV=sandbox`（2023年のデータを約30秒に1回配信、10分で切断）。

Wolfxは **WebSocket** で受ける（`wss://ws-api.wolfx.jp/jma_eew`、張りっぱなし）。
HTTPを叩くのは起動時の2回だけ:
Wolfxの現在値1回（WSが繋がるまでの空白を埋める）と、P2P `/history` 1回。
以後はWebSocketだけで回る。時刻推定もWolfxの pong で行い、HTTPポーリングはしない。

```sh
npx vite-node tools/probe.ts 240              # 本番に繋いで確かめる
npx vite-node tools/probe.ts 120 sandbox      # サンドボックス
```

## 実測して分かったこと

### P2P `/history` のCORS → **通っている**

```
$ curl -sI -H "Origin: http://localhost:5173" \
    "https://api.p2pquake.net/v2/history?codes=551&limit=1"
access-control-allow-origin: *
```

本番・サンドボックス・Wolfxの3つとも `access-control-allow-origin: *`。
プロキシは不要で、起動時の履歴取得はブラウザから直接できる。
（取れなかった場合に備えて、`VITE_FETCH_HISTORY=false` で
「WebSocket接続後に届いたものだけ表示する」に倒せる。degraded表示も出る。）

レート制限（`/history` 60req/分）に触れないよう、RESTは起動時の1回だけ叩く。

### 本番の無音の間隔（2026-08-16、4分間の実測）

| ソース | 届くもの | 間隔 |
|---|---|---|
| Wolfx | `{"type":"heartbeat","ver":22,"id":…,"timestamp":<epoch ms>}` | 60秒ごと |
| Wolfx | `{"type":"pong","timestamp":<epoch ms>}`（こちらの ping への応答） | 送った分だけ |
| P2P | 地震情報と、不定期の各地域ピア数（code 555） | **接続から最初の555まで3分以上空くことがある** |

したがって **「p2p 受信中」は接続が生きている証明にならない**。
無音を根拠に切ると誤って繋ぎ直すので、P2P側の監視は10分と緩くとり、
代わりに最終受信時刻を画面に常時出して判断できるようにしてある。
Wolfxは毎分来るので90秒無音で切る。

Wolfxのハートビートと pong は epoch ms のサーバー時刻を載せている。
pong は自分の ping への応答なので往復時間が分かる。HTTPの `Date`（秒単位）より
分解能が高いので、時刻推定はこちらを主に使う。
実測ではこのマシンの時計がサーバーより約2秒遅れていた。

### フィクスチャ

| ファイル | 中身 |
|---|---|
| `fixtures/history.json` | `/history` 直近50件（2026/08/14〜16）。通常運用の姿 |
| `fixtures/quake.json` | 能登半島地震 2024/01/01 の code 551 が4件。極端な例 |
| `fixtures/wolfx_warn.json` | 予報から切り替わった報（2026/04/01 茨城県南部 M5.1 第12報） |

動作確認のEEWシナリオは **地震が起きる少し前**（発震の2秒前）から始まる。
そこから実データどおりの間隔で報が届く（発震から4秒・12秒・30秒・56秒）。
予報円が0から広がる様子と、第1報が届くまでの空白まで再現できる。

シナリオは `wolfx_warn.json` を土台にしている。
合成データを別に持たず、実際に流れた報をそのまま流す。
変えるのは EventID と時刻、そして報を重ねるために必要な値
（報番号・規模・予測震度・警報かどうか・対象地域の有無）だけ。
EventID を毎回変えるのは、同じIDだと2回目に報番号が戻って重複排除で捨てられるため。

`wolfx_warn.json` で分かったこと:
`MaxIntensity` は `"5弱"`（`"5-"` とは限らない）。
`WarnArea` は `Chiiki` / `Shindo1`（上限）/ `Shindo2`（下限）/ `Time` / `Type` / `Arrive` を持ち、
`Time` に `"//////"`（到達予測なし）が入る。
地域ごとの `Arrive` に PLUM 法とあっても、震源の確からしさは `Accuracy.Epicenter` で見る。

実測値は仕様書の記述と一致した。
history: 平均1.3KB・最大16.6KB・全体70KB、DetailScale 45 / ScalePrompt 2 / Destination 2 / Foreign 1。
quake: DetailScale 1件で320KB・2829観測点、`scale: 46` が3点、M7.4→M7.6の訂正あり。

両方をゴールデンテストで固定してある（`test/adapters.p2p.test.ts`, `test/store.test.ts`）。

## 実装上の判断

### 欠損センチネルはフィールドごとに独立

- 緯度は `-200` との**厳密比較**で判定する。`< 0` では南半球の遠地地震を落とす。
- 深さ・マグニチュード・最大震度はそれぞれ独立に `-1` を判定する。
  遠地地震は「震源はあるが深さだけ無い」。
- `depth: 0` は「ごく浅い」であって不明ではない。

### 震度 46

「5弱以上と推定されるが震度情報を入手していない」。
ソート用の数値（46）と表示ラベル（`5弱以上`）を分けて持つ（`Intensity`）。

### 同一地震のマージ

P2Pの地震情報にEventIDは無いので `earthquake.time` をキーにする。
発表種別ごとに持ち込む情報が違う（`Destination` は震源、`DetailScale` は震度）ので、
置換ではなく要素ごとにマージする。順序が逆転しても結果が変わらないことをテストで固定した。

### 区域別の震度は地図に打たない

`points` には座標が無い。観測点別（`isArea: false`）は気象庁の観測点一覧
（`JMAstations.json`）から実座標を引いて打つ。
区域別（震度速報）は面であって点ではないので、代表点を自前で作らず、地図には打たない。
気象庁が発表していない位置を発表内容として描かないため。
打てない点（区域別・観測点一覧に無い名前・表示範囲外）は地図では黙って落とす。
震度そのものは詳細の一覧に出ているため。区域ポリゴンを入れたら塗る。

### フェイルサイレント禁止

- wolfx / p2p の接続状態を常時個別表示（`未接続 / 接続中 / 受信中 / 無音 / 再接続待ち / 停止 / 異常`）
- 時刻オフセットが未推定・異常ならその旨を表示
- 解析失敗の件数、履歴取得の失敗を画面に残す
- 数値が `NaN` / `Infinity` になったら表示しない（`null` を「不明」として出す）

### 名称

このアプリ自身の出力として「緊急地震速報」「速報」を使わない。
気象庁が発表した `Title` はそのまま表示する。テストで固定してある（`test/ui.test.ts`）。

例外は**津波の階級**で、`MajorWarning` / `Warning` / `Watch` を
**大津波警報 / 津波警報 / 津波注意報**と表示する。
これは気象庁の階級そのものの呼称であって、こちらが作った名前ではない。
コードのまま出しても意味が伝わらない。

### 津波の見せ方

一番大きく出すのは**高さ**（30px）と**いつ来るか**（18px）。判断を決めるのはこの2つで、
区域名と階級名はその手がかりなので小さい。
「直ちに来襲」「津波到達中と推測」は時刻より強い情報なので、時刻より優先して出す。

背景は気象庁の津波警報等の配色で塗る（薄めない）。

### 避難の呼びかけ

津波の列の**最上部**に、いちばん重い階級に応じた行動を出す。

| 階級 | 出す文言 |
|---|---|
| 大津波警報・津波警報 | いますぐ高台へ避難 |
| 津波注意報 | いますぐ海から上がる |

文言は気象庁の呼びかけに合わせる。こちらで考えた指示は出さない。

公開しないので、予報業務としての制約は考えない。ただし嘘は書かない:

- **過去の発表では出さない**（`historical`）。サンドボックスの再生や接続直後に
  投げ込まれた古い報で避難を促すのは、この道具が嘘をつくのと同じ
- 区域と現在地の対応データを持っていないので「あなたの地域は」とは言わない。
  全体としての呼びかけに留める

| 階級 | 背景 | 文字 |
|---|---|---|
| 大津波警報 | 紫 `#C800FF` | 白 |
| 津波警報 | 赤 `#FF2800` | 白 |
| 津波注意報 | 黄 `#FAF500` | 黒 |

## P波・S波の予報円

`public/assets/tjma2001.txt`（気象庁 JMA2001 走時表、850KB）を起動時に一度だけ読み、
`src/lib/travelTime.ts` がメモリに保持する。バンドルには入れない。

- 半径は**地震発生時刻からの経過秒数**で毎フレーム引き直す（発表時刻ではない。前回からの外挿もしない）
- 走時表が返すのは**震央距離**（地表に沿った距離）。そのまま円の半径にする。深さで補正し直さない
- 地図ライブラリを使っていないので、球面上の等距離点128個を投影した多角形として描く（`src/lib/geo.ts`）
- 経過時間には補正済みの時刻（`clock.now()`）を使う

描く／描かないの判定は `src/lib/waveCircles.ts` の1関数に閉じている。
**深さでも震源決定手法でも除外しない。** 描かないのは「そもそも描けない」場合だけ。

| 条件 | 円 |
|---|---|
| 深発地震（150km超） | **描く**。走時表は700kmまで値を持つ。深いぶん円の出現が遅れるだけ |
| PLUM法 | **描かない**。震源を決める手法ではないので、震源から広がる波として描けない |
| 予報／警報 | **どちらも描く**（判定に電文種別を混ぜない） |
| 取消報 | 即座に消す |
| 走時表が未読込・波が未到達・表の範囲外・震源要素なし | 描かない（0kmの円を描かない） |

EEW受信中は**震央マーカーを滑らかに点滅させる**（色ではなく動きで示す）。

### S波が地表に出てくるまでのリング

深い地震では、発震から数十秒のあいだ**円が1つも出ない**（深さ170kmならS波43秒）。
波は震源から上がってきている途中で、地表にはまだ出ていないためだが、
地図に何も無いと「まだ何も起きていない」と読めてしまう。
そこで震央の印のまわりに、S波が地表に出るまでの進み具合をリングで出す。

```
発震 ──────────────────────────────► S波が震央直上に出る ──────►
     赤いリングが12時から反時計回りに満ちる    リングを消す
                                （同時にS波の予報円が生まれる）
```

- **見るのはS波だけ**。被害を出すのは主要動で、P波の到達はその途中の目印にすぎない。
  2段階にすると途中で一度満ちて数え直すので、何が満ちようとしているのかが読めなくなる
  （P波の予報円が出るのは途中。リングはそこで区切らず、発震からの通算で数える）
- 進み具合も円の半径も**同じ走時表・同じ深さ**から引いているので、
  **リングが一周した瞬間にS波の予報円が生まれる**
  （`surfaceStatus()` と `waveRadii()`。ずれないことをテストで固定してある）
- 12時から**反時計回り**に、**ひとつの弧が**一周ぶん伸びる。SVGの circle は
  3時始まり・時計回りなので、`rotate(-90)` で始点を12時に移し、縦軸で鏡映して向きを返す
  （向きは実ブラウザの当たり判定で実測して確認した）
- **`vector-effect: non-scaling-stroke` は使えない。** これを付けると破線の刻み
  （`stroke-dasharray`）まで画面座標で解釈され、一周ぶんに指定した長さが円周と合わなくなって、
  **円の全周に赤い破片が散る**。半径・線の太さ・刻みはすべて座標系の値として渡し、
  倍率は `waves.ts` で掛ける（刻みが円周と1対1であることをテストで固定した）
- 色はS波の予報円と同じ赤。半径は震央の×印の倍ほど外側（同じ赤なので近いと見分けが付かない）。
  拡大しても見かけの大きさは変えない
- PLUM法・取消では出ない（予報円と同じ判定に乗っている。そもそも震源が無い）
- 深さ0km（走時0秒）では出ない。走時表が読めていないときも出さない
  （待ち時間が分からないのに0や満了を描かない）

PLUM法の報では**×印を出さない**。PLUM法は観測された揺れからその周辺の揺れを
予測する手法で、震源も発震時刻も決めていない。震央を指す印は誤りになるので、
「このあたりで揺れている」ことだけを示す、ぼんやり光る円を点滅させる。

### 震源決定手法（PLUM法）の判定

配信元の和訳文字列ではなく、**生電文 `RK` の1桁目**（震央の確からしさ）で見る。

```
... 51 5- RK44559 RT01/// RC0//// 9999=
             ^ 4 = IPF法（5点以上）。9 = PLUM法
```

0 不明・未定 / 1-4 IPF法（点数別）/ 5 防災科研 / 6 海洋研究開発機構 /
7 気象研究所 / 8 予備 / **9 PLUM法**。
実データ2件（`RK44559`・`RK44209`）で、コード 4 と `Accuracy.Epicenter` の
「IPF 法（5 点以上）」が一致することを確認済み。
**コード 9 の報は未観測**なので、そこはテストで形を固定してあるだけ。
電文を持たない配信元のために、文字列（「PLUM 法」等）も併せて見る。

イベントIDごとに状態を持つので、複数のEEWが同時進行しても干渉しない。

## 報が更新されたときの引き直し

続報では震源も深さも規模も動く。**第1報の値を持ち続けると、画面の数字だけが古いまま残る**
——いちばん静かに嘘をつく壊れ方なので、値を覚える箇所を作らない方針にしてある。

| 表示 | 引き直しの契機 |
|---|---|
| EEWのカード（最大予測震度・震源・M・深さ・対象地域） | `eventId:serial:isCancel` が変わったら組み直す。**古い／同じ報番号は store が捨てる**ので、内容だけ変わって番号が同じことは起こらない |
| この地点の推定震度・到達カウントダウン | 毎回計算する（記憶しない）。報の受信時と、**1秒ごとの再描画**の両方で更新される |
| 予報円・震央のリング | 報ごとに震源要素を差し替え、半径と進み具合は**毎フレーム走時表から引き直す**（前回値からの外挿はしない） |
| 地図の震央マーカーと寄せる範囲 | 震源の緯度経度が変わったら |
| 地図の観測点 | 観測点の**全点の指紋**（名前と震度）が変わったら |

震源要素は予報円・予測震度・到達予測のいずれも 0.1度・10km に丸めて使うので、
丸めの幅より小さい移動では数字が動かない（これは意図した挙動）。

観測点の指紋は当初「件数と先頭の1点」だけを見ていた。**続報で観測点の数が変わらないまま
中ほどの震度だけが訂正されると、地図が古い色のまま残る**（最大震度が動かなければ
並び順の先頭も変わらないので気付けない）。全点を見るように直し、テストで固定した。

## 震度予測（計算のみ。UIには出していない）

`src/lib/intensityPrediction.ts`。式は気象庁「緊急地震速報検討委員会 資料2-1
（平成20年3月18日）」のもの。

| 段 | 式 | 出典 |
|---|---|---|
| 0 | `Mw = Mjma − 0.171` | 宇津(1982)・佐藤ほか(1989) |
| 1 | `log10 L = 0.5Mw − 1.85`、`X = max(R − L/2, 3)` | 宇津(2001) |
| 2 | `log10 PGV600 = 0.58Mw + 0.0038D − 1.29 − log10(X + 0.0028·10^0.5Mw) − 0.002X` | 司・翠川(1999) |
| 3 | `PGV = PGV600 × (600/AVS30)^0.66` | 松岡・翠川(1994) |
| 4 | `I = 2.68 + 1.72 log10(PGV)` | 翠川ほか(1999) |

- 震源要素は気象庁と同じ粒度（緯度経度0.1度・深さ10km、0kmなし）に丸める。
  報ごとの微動で予測が跳ねるのを防ぐため
- **上限**は断層面までの最短距離 X、**下限**は点震源の距離 R。
  気象庁の「震度○○から○○」はこの2つ
- 深さ150km超では予測しない
- 距離減衰式は深さ50km以浅が対象。超えたら `beyondAttenuationDepth` を立てる
- 第4段の回帰は震度4以上が対象。下回ったら `belowRegressionRange` を立てる

資料の計算例（Mjma 7.0 / 深さ20km / 震央距離50km / AVS30 250）を
全桁ゴールデンテストで固定してある。

### 観測点ごとの計算と地域集約

気象庁は約4000点の震度観測点それぞれで震度を計算し、**地域単位で最大値を代表**として
発表している。`src/lib/stationPrediction.ts` がその集約（`predictStations` → `maxByArea`）。

データは `public/assets/stations-avs30.json`（675KB、4416点）。

| 項目 | 出典 |
|---|---|
| コード・名称・緯度経度・所属地域 | 気象庁 震度観測点一覧（`JMAstations.json`） |
| AVS30・微地形区分・メッシュコード | 防災科研 J-SHIS 表層地盤データ V4（2020年版） |

作り直しは `python3 tools/build-avs30.py JMAstations.json public/assets/stations-avs30.json`
（4416点を1点ずつ引くので30分ほど。途中経過は `tools/.cache/` に貯まり再開できる）。

- J-SHISは `position={経度},{緯度}` の順。逆にすると日本の外を指す
- ARV ではなく **AVS** を取る。ARVは工学的基盤Vs=400m/s基準で、
  震度予測の式（600m/s基準）と揃わない
- **`AVS = 0` は水域**（沿岸海域・湖沼・河道）で地盤データ無しの意味。
  そのまま使うと増幅率 `(600/0)^0.66` が発散する
- 観測点一覧の座標は小数2桁（約1.1km）で、J-SHISの250mメッシュより粗い。
  海岸沿いの点が海側のメッシュに落ちるため、124点は近傍（0.3〜0.6km）で代用した。
  代用した点には `fallbackKm` が入る（実測値と見分けられるように）

### 主要動の到達予測（カウントダウン）

`src/lib/arrival.ts`。**予報円とまったく同じ走時表・同じ丸め・同じ補間**を通す。
別実装にすると「S円が届いているのに残り5秒」のような食い違いが出て、
どちらが正しいか分からなくなる（`waveRadii` の逆が `travelTimes`。両者の
往復が一致することをテストで固定してある）。

```
Δ = 震央距離（大円距離）
Ts = 走時表(丸めた深さ, Δ)
到達予測 = OriginTime + Ts
残り = 到達予測 − 補正済み現在時刻
```

- **深さで足切りしない**（気象庁は150km超で主要動到達予測を行わないが、
  走時表は700kmまで値を持ち、予報円も描いている。円と数字を揃える）
- **PLUM法では出さない**。震源を決めていないので走時が引けない。
  気象庁自身も `Arrive` に「主要動到達時刻の予測なし（PLUM 法による予測）」と入れる
- 表の外（震央距離2000km超）は外挿しない

**表示は0.1秒まで出す。** 精度と表示の刻みは別の話で、真の到達時刻とは±数秒ずれる
（時刻補正±0.5秒、走時表の刻み、そして最も大きいのは震源要素の推定誤差）が、
刻みを粗くしても誤差は減らない。公開しない個人用の計器なので、秒未満を隠して得るものが無い。

**到達したら 0.0秒 のまま止める。** 経過秒数を数え上げないのはもちろん、
「到達」のような文字にも変えない——数字が文字に化けると、桁も幅も組み方も変わって、
同じ場所の同じ値には見えなくなる。0.0 は「もう残りが無い」を数字のまま言える。
数字を出さないのは値が取れないとき（`—`）だけ。

**0.0になっても赤は解かない。** 止まっている今がまさに揺れている時刻で、
ここで色が引くと「終わった」に読める。赤が引くのはEEW自体が消えるとき。

- 0.1秒に**切り上げる**（まだ届いていないのに 0.0秒 とは出さない。0.0は到達後だけ）。
  丸めは**整数にしてから割る**——`0.1` を掛けると `23.200000000000003` が出る
- **1秒ごとの再描画では足りない**（数字が1.0ずつ飛ぶ）。カウントダウンだけが
  `requestAnimationFrame` で自分を書き替える。回すのは到達前だけで、到達したら止める
  （過ぎた時間を数え上げても読む値にならない）。時計（`setClock`）を渡されていなければ
  回さない——時刻が進まないので無駄

組み方:

- **整数部だけ大きく**（44px）、小数部（24px）と添え字（あと・秒、15px）は小さく置く。
  全部同じ大きさだと桁が増えて見え、数字が読みにくい
- **残り10秒**から地を赤で塗る。身構えるのに要る時間（火を止める・机の下に入る）
  から決めた。3秒では赤くなってから何かする余地が無い
- 差し迫っているあいだは**赤い字ではなく地を赤で塗る**。警報のカードは地色が赤に寄り
  ストライプも赤なので、赤い字を足すといちばん動きのある値が埋もれる。
  **数字は隠さない**（「まもなく」に置き換えない）
- 数字と文字は同じ枠を使い回すので、**使わない側は空文字にする**。
  `hidden` にしただけでは文字列として残り、読み上げや取り出しに混ざる

**P波の残り秒数は出さない**（一度入れて、やめた）。理由は3つ:

- 行動を決めるのは主要動。P波の残り秒数を読んで何かする場面が無い
- 秒で動く数字が2つ並ぶと、大きいほうが何の数字か曖昧になる
- P波が地表に出たことは地図の白い円で見える。数字で二重に持つ必要が無い

その場所は「主要動到達まで」という見出しにした。状態で変わらない文字だが、
**何のカウントダウンかを言う**ぶんの情報はあるし、消える行が無くなる。

### 状態が変わっても枠の大きさを変えない（幅も高さも）

到達の前後で高さが動くと、隣の震度も下の行も連れて動いて、画面の統一感が崩れる。
実ブラウザで3状態（残り14秒・残り1.6秒・到達済み）を並べて測り、
`.estimate` の高さと下の行の位置が**小数点以下まで一致**することを確認してある。

- 見出しは消えない（消える行を作らない）
- 数字の行は `min-height: 48px`。字の大きさが変わっても枠の高さは同じ。
  中身は縦中央に置き、数字どうしの縦位置は内側の要素でベースラインに揃える
- 差し迫ったときの余白は**常に確保**しておき、変えるのは地の色だけ
  （`--imminent` で padding を足すと、そのぶん高さが動く）
- 計算できないときの理由書きも同じ高さを取る（`min-height`）

幅も同じ理由で固定する。HUDは中央寄せなので、**桁が減るたびに全体が左右に揺れる**。

- 到達予測の枠に固定幅（232px）を与える。「100.0秒」が収まる幅
- 整数部は**3桁ぶんの場所を空けて右詰め**（`min-width: 3ch; text-align: right`）。
  さらに `font-variant-numeric: tabular-nums` を明示する——等幅数字でないと
  「1」と「2」で送り幅が違い、桁が変わったときに「秒」の位置が動く
  （実測で3桁のときだけ3.6pxずれていた。明示して0になった）
- **「あと」は付けない。** 見出しが「主要動到達*まで*」と言っているので重複だし、
  数字を右詰めで固定すると1桁のときに「あと」との間が空いて見える。
  数字の左に何も置かなければ、空きは枠の余白と区別が付かない
- 実ブラウザで4状態（残り9.2秒・14.0秒・123.4秒・0.0秒）を測り、
  **HUDの幅・位置と「秒」の位置がすべて一致**することを確認してある
- 理由書き（「深さ150km超」など）も `white-space: nowrap`。折り返すと背が高くなる

対象地域の一覧には、**気象庁が出している地域ごとの到達予測時刻**（`WarnArea` の
`Time`）を添える。自前計算より確かなので、あるならそちらを使う。
`//////`（予測なし）や「既に到達と予測」はその旨を出す。

### 設定した地点の推定震度

初回起動時に現在地の設定を案内する（断れば二度と出ない。設定からいつでも開ける）。
設定方法は「現在地を使う」（端末の位置情報）と「地図をクリック」の2つ。

その地点の AVS30 は、**設定したときに一度だけ** J-SHIS から引いて端末に保存する
（`Access-Control-Allow-Origin: *` を実測で確認済み）。位置情報は端末の外に出さない。
地盤データを引くときだけ座標をJ-SHISに送る。

### 予報と警報の差、津波との重なり

- **警報のカードは予報より緊迫して見せる**。**左端に縦の**赤白ハザードストライプ、
  地の色を赤に寄せ、タイトルも赤にする。予報は素のまま。
  ストライプを横帯にしないのは、津波の帯・震度の色面と合わせて色の面が縦に3つ積み、
  どれが緊急度を表しているのか読めなくなるため（縦なら色の面が横に並ぶ）
- **津波が発表されている間は、あらゆるEEWのカードに「津波情報 発表中」を載せる**
  （余震のカードにも）。色はいちばん重い階級のもの
- 津波の判定が出ていない間は「津波 調査中」（気象庁の言い方に合わせる）

### EEWの置き方（列にせず、地図に重ねる）

```
┌──────────────────────────────────────┬─────────┐
│ ┌───────────────┐                     │ 一覧    │
│ │[津波情報 発表中]│ ← 発表中だけ         │ 熊本…   │
│ │ 最大予測 [5−]  │                     │ 日向灘…  │
│ │ 気象庁のTitle   │                     │         │
│ │ 震源名          │      地図           │         │
│ │ M・深さ         │   （幅は変わらない）  │         │
│ │ 第N報・発表時刻  │                     │         │
│ │ [最終報][PLUM法]│                     │ 時計    │
│ │ 強い揺れ N地域  │                     │         │
│ └───────────────┘                     │         │
│  津波の判定待ち                          │         │
│  2件目以降のEEW（余震など、控えめ）        │         │
│                                        │         │
│      ┌────────────────────────┐        │         │
│      │この地点 主要動到達まで     │        │ status  │
│      │        あと 14.0秒 [3] … │        │         │
│      └────────────────────────┘        │         │
└──────────────────────────────────────┴─────────┘
```

**列にしない理由**: 列だと受信のたびに地図の幅が変わり、再投影で
**震源の位置が画面上で飛ぶ**。「地図と一覧は動かさない」という方針に反していた。
左列は上半分しか埋まらず、地図の幅を360px損ねていた。重ねれば地図は常に同じ大きさで、
平常時は幅いっぱいを使える。列として開くのは津波だけ（区域と高さを縦に並べるため）。

**この地点の値（到達カウントダウンと推定震度）は地図の下・中央のHUDに置く。**
地図を見ているときに視線が置かれる場所で、秒で動く値をそこに出す。
カードの中に入れていたときは、全国の最大予測震度と同じ形のバッジが隣に並んで、
どちらがどこの震度か分からなかった。**場所で分け、それぞれに名前を付ける**
（カード＝「最大予測」、HUD＝「この地点」）。

- 枠は伸ばし放題にしない。対象地域が多いときは `max-height` で枠内スクロール
  （下中央のHUDと重ならない高さに収める）
- HUDは横一列に組む（縦に積むと下端から高く伸びて地図を隠す）。
  地の色は不透明——半透明にすると地形や予報円が数字に透けて、いちばん読ませたい値が読みにくい
- HUDは `pointer-events: none`。地図をクリックして現在地を指す操作を邪魔しない
- 余震の段では広げない（主役は最新の1件）。**透過はかけない**——
  震度の色は規格色なので、薄めると別の階級に見える。落とすのは文字と数字の大きさだけ

「最終報」＝これ以上更新されない、は報番号より重い情報なので、薄い字に混ぜず
印にする。枠線ではなく地を塗るのは、枠線だと押せるもの（設定・全域）と同じ見た目に
なるため。

取消の報では**震源名を大きく出さず**、この地点の枠も付けない
（無かったことになった揺れの到達予測は意味を持たない）。カード全体を落として、
通常の報と見分けが付くようにする。

津波の判定待ちを確定値より後ろにするのは、あれが「まだ分からない」という保留の
情報だから。余震より前に置くのは、連続しても画面外に押し出されないようにするため。

取消の報では到達予測も推定震度も出さない（無かったことになった揺れの予測は意味を持たない）。
取消と進行中が混在するときは、**進行中のいちばん新しいもの**をHUDに出す。

### 対象地域の並べ方

- 震度別にまとめて**全件**出す。見出しはこのアプリの言葉になるので「強い揺れ」と書く
- まとまりの中は**到達の早い順**。気象庁の並び順は地域コード順で、探す役に立たない
- 気象庁が出している到達予測時刻を添える（自前計算より確か）。時刻は**地名と別の要素**
  にする——文字列に足すと時刻が地名の一部に見える。地名も読点でつながず、間隔で分ける

- 計算できないときは黙って空にせず理由を出す
  （`PLUM法（震源なし）` / `震源が未確定` / `規模が未確定` / `深さ150km超` / `地盤データなし`）

**これは気象庁の発表ではなく自前の計算で、誤差は±1階級が常態**
（気象庁自身の評価でも一致21%、±1階級以内75%）。
第4段の回帰は震度4以上が対象で、それ未満は精度が保証されない。
距離減衰式は深さ50km以浅が対象で、それより深いと過大に出る。
**この断りは画面には出していない**（毎回同じ文は壁紙になり、可変値の邪魔をするため）。
読むのは作った本人だという前提で、経緯はここに置く。

### 設定画面は素のHTML

右下の「設定」で開く画面は、**ブラウザ既定の見た目のまま**にしてある
（白地・既定のフォント・見出し・箇条書き・素のボタンとチェックボックス）。

- ここは**平常時に開いて読むだけ**の画面で、緊急時の視認性とは関係が無い。
  作り込むと、直すたびに本体の計器と二重に手が要る
- 受信状態は色の丸ではなく**文字**で言う（`wolfx 受信中（最終受信 19:00:05）`）。
  緑の丸が何色だったかを思い出すより速い
- アプリ側の指定（暗色・独自フォント・`font-variant-numeric`・`button` の font 継承）を
  `revert` で打ち消す。**`color-scheme: light` を忘れない**——`:root` が `dark` のままだと、
  ボタンもチェックボックスもOSの暗色版で描かれて「素のHTML」にならない
- 残した装飾は太字だけ（時刻ずれ異常・劣化理由。読み飛ばすと困るもの）

### 一覧の見せ方

- 見出しは持たず、**先頭の行を大きく**して最新だと示す
- **番号は振らない。** どれを見ているかは**発震時刻**で突き合わせる
  （詳細の見出しが `詳細 08/16 18:05`、一覧の行にも同じ時刻がある）。
  `#0` から番号を振っていたが、時刻という自然な鍵がすでに両方に出ているので、
  番号は覚える手間だけを増やしていた
- 右の列は **360px**（もとは420px）。実測でいちばん長い組み合わせ
  （長い震源名・M10.0・深さ700km・大津波警報）でも収まり、深さと時刻の間は
  通常の行で34px空く。420pxのときはそこが90px以上空いていた
- **津波の有無は震源名の行の右端**に、日本語で出す（`Warning` では何のことか分からない。
  階級名は気象庁のもの）。M・深さの欄に置くと、空のときでも幅を取って
  深さと時刻の間が間延びする。色は階級の色に合わせるが、**文字色だけ**
  （震度の箱と色の面で競合させない）。「なし」「不明」は出さない
- 震度の箱は**行の高さいっぱい**、左端いっぱいから始める（色の帯として読ませる）。
  **数字を大きく（25px、先頭の行は32px）、箱は狭く（50px、先頭の行は62px）。**
  箱の幅は全行で揃える——揃えないと下の「M・深さ」の区切り線が行ごとにずれる
- 「5弱以上」（`scale 46`）だけ添え字が付いて横に伸びるので、その添え字は10pxに詰めて
  折り返させない。**消さない**——「5弱」と「5弱以上」は別の情報。
  P2Pの仕様では `earthquake.maxScale` に 46 が入りうるので、来ても崩れないようにしてある
- マグニチュードと深さは間隔ではなく**縦線**で区切り、列幅を固定して
  上下の行で線の位置を揃える
- 発震時刻は**秒まで**出す
- 観測点の数は一覧ではなく詳細に書く
- 詳細（観測点名の一覧）は**既定で出さない**。震度の分布は地図に出ているため。
  設定の「表示」から出せる（`localStorage` に覚える）。折りたたみは持たない
  ——出すか出さないかだけ
- 詳細を出していないあいだ、その位置には**時計**が出る。
  出すのは補正済みの時刻（端末の時計そのままではない）で、**JSTと明記する**
  （このアプリの時刻表示はすべてJST固定。端末のタイムゾーンに従わない）
- **新しい地震が来たら、そこへ移る**（古いものを手で選んでいても新着が主役になる）

### 項目の並べ方

複数の項目を並べるとき、**区切りに文字（「/」など）を使わない**。
`display: flex` の間隔で分ける（`src/ui/dom.ts` の `fields()`）。
文字で区切ると、値そのものと区切りの見分けに一手間かかる。

### 画面に文字を置く基準

その文字が**画面の状態によって変わるかどうか**。変わらないなら、それは読み手が
既に知っていることなので、画面ではなくこのREADMEに書く。
常時出ている説明文はゼロ。画面に残すのは、値・状態・例外・押せるもののラベルだけ。
- 地盤データが引けなかった地点では**計算しない**。増幅なしで代用すると
  その地点だけ実際より小さい震度が出る

観測点4400点ぶんの面的な描画は**まだ繋いでいない**（見せ方が未決）。

## 今回のスコープ外

主要動の到達予測・予測震度の計算、長周期地震動、南海トラフ地震臨時情報、通知・音声アラート。

次フェーズのための拡張点だけ用意してある。

- 正規化イベントに震源の緯度・経度・深さ・発震時刻が入っている
- `EewEvent.epicenterReliable` — `Accuracy.Epicenter` に PLUM / レベル / 未定 / 不明 を含む報、
  および `isAssumption` の報では false。震源に基づく計算をしてはいけない印
- `src/observer.ts` — 現在地の保持（未設定なら null。0として扱わない）
- `src/clock.ts` — サーバー時刻との差の推定（Wolfxのpong優先、中央値・往復の半分を控除）

### フォントの持ち方

- **CDNは使わない**（オフラインで起動することが条件）。`src/assets/` に同梱する
- 欧文・数字の直立は可変フォント1本（wght 100-900、35KB）。
  斜体は**本物のイタリック体**（傾き -11.3°、数字も収録、17KB）を別に持つ。
  斜体を持たないフォントだとブラウザが機械的に傾けるだけで字形が崩れる
- tabular figures 対応なので、時刻や座標の桁揃えを等幅フォント無しでできる
- 日本語は全グリフ4.2MBあるので、**このアプリが出す文字だけ**に絞ってある
  （観測点名・市町村名・区域名・都道府県名・UIの文言＝1630文字、610KB、可変1本）。
  静的2本（400と700）だと649KBで、可変のほうが小さく太さも自由に使える。
  作り直しは `python3 tools/build-jp-font.py`（要 fonttools と brotli）。
  絞った字種の外が来たら端末のゴシックに**字ごとに**落ちる（豆腐にはならない）

## 震度の表記

「5弱」ではなく **5 と − に分けて組む**。漢字を混ぜると数字と見かけの大きさが揃わず、
一番大きく出したい値が読みにくくなるため。数字も符号も斜体で、符号はさらに小さく少し上に置く。
気象庁の正式表記（5弱）は `title` 属性に残してあるので、元の表記も引ける。
46（5弱以上と推定されるが震度情報を入手していない）は `5−` に「以上」を添えて、
不確かさを消さない。
