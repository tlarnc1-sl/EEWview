# EEWview

日本の緊急地震速報・地震情報・津波予報を1画面で眺めるための、個人用のブラウザアプリ。
フレームワークも地図ライブラリも使わず、素のDOM操作とSVGだけで描く。

**リポジトリはPublicだが、これはホスティングされたサービスではない。**
ここにあるのはソースコードで、動かすには各自がクローンしてビルドする。
気象庁の「予報業務許可」が要るのは**予報や警報を一般向けに反復継続して発表・伝達する行為**
（＝サイトやアプリとして公開・運用すること）で、ソースコードを読める状態にしておくこと自体は
それに当たらない。詳しくは [公開の位置づけ](#公開の位置づけ) を参照。

## これは何でないか

**防災アプリではない。** 命を守る役割は気象庁や、Yahoo!防災速報・NERV防災アプリなど
許可事業者のサービスが担う。これは「今この瞬間、日本のどこで何が起きているか」を
眺めるための計器盤で、UI文言もその立場で選んである（[名称](#名称)を参照）。

震度予測・到達予測は自前の計算であって気象庁の発表ではない（[震度予測](#震度予測)を参照）。

## 使い方

```sh
npm install
npm run dev        # 既定は本番（Wolfx + P2P地震情報 本番）
npm test           # Vitest（368件）
npm run typecheck  # tsc --noEmit
npm run build      # dist/ に静的ファイル一式
```

接続先は `.env.local`（`.env.example` を参照）。実装を試すときだけ
`VITE_P2P_ENV=sandbox`（2023年のデータを約30秒に1回配信、WebSocketは10分で切断される）。

```sh
npx vite-node tools/probe.ts 240              # 本番に繋いで実測する（秒数を指定）
npx vite-node tools/probe.ts 120 sandbox      # サンドボックス
```

Wolfxは **WebSocket** で受ける（`wss://ws-api.wolfx.jp/jma_eew`、張りっぱなし）。
HTTPを叩くのは起動時の2回だけ——Wolfxの現在値1回（WSが繋がるまでの空白を埋める）と、
P2P `/history` 1回。以後はWebSocketだけで回る。時刻推定もWolfxの `pong` で行い、
HTTPポーリングはしない。

## 構成

```
src/
  transport/   WebSocket・再接続・ハートビート監視（どのソースかを知らない）
  adapters/    wolfx.ts / p2p.ts — 生JSON → 正規化イベント
  store/       重複排除・順序逆転の始末・同一地震のマージ
  lib/         震度予測・到達予測・走時表・PLUM法判定など、UIを持たない計算
  ui/          素のDOM描画（フレームワークなし）
  clock.ts     サーバー時刻とのずれの推定
  observer.ts  現在地の保持（未設定なら null。0として扱わない）
  types.ts     正規化イベントの型
tools/
  build-map.py        japan.geojson → src/ui/japan.json（47都道府県）
  build-stations.py   JMAstations.json → src/ui/stations.json（観測点の座標）
  build-avs30.py      観測点ごとにJ-SHISからAVS30を引く（震度予測用）
  fill-avs30-gaps.py  海側メッシュに落ちた点を近傍で代用する
  build-jp-font.py    このアプリが出す文字だけに絞った日本語フォントを作る
  probe.ts            実接続してCORS・無音間隔などを確かめる
```

`transport` は繋ぎ先を知らない。URLとタイムアウト値だけを受け取り、生のペイロードを流す。
中身の解釈は `adapters/` の仕事で、UI層は正規化イベントしか見ない。データ元を
差し替えるときは `adapters/` だけを触ればよい。

## データの経路

| 接続 | 取るもの |
|---|---|
| Wolfx `wss://ws-api.wolfx.jp/jma_eew` | 緊急地震速報（予報・警報とも） |
| P2P地震情報 API v2 `wss://api.p2pquake.net/v2/ws` | 地震情報（551）と津波予報（552）だけ |

**EEWはWolfx一本**にしている。P2Pの556（警報）と554（発表検出）は受け取らない。
556は警報級しか流れてこないうえ、経路が2つあると先着の採用と重複の始末が要る。
その代わり、Wolfxが落ちている間はEEWが一切来なくなる。接続状態の表示で判断すること。

受信データ（EEW・地震情報・津波）の一次情報は**すべて気象庁**で、WolfxとP2P地震情報は
その中継。中継元それぞれの利用条件に従うこと。

### CORSと無音間隔（実測）

```
$ curl -sI -H "Origin: http://localhost:5173" \
    "https://api.p2pquake.net/v2/history?codes=551&limit=1"
access-control-allow-origin: *
```

本番・サンドボックス・Wolfxの3つとも `access-control-allow-origin: *`。プロキシは不要で、
起動時の履歴取得はブラウザから直接できる（取れなかった場合は `VITE_FETCH_HISTORY=false` で
「WebSocket接続後に届いたものだけ表示する」に倒せる。degraded表示も出る）。
レート制限（`/history` 60req/分）に触れないよう、RESTは起動時の1回だけ叩く。

| ソース | 届くもの | 間隔 |
|---|---|---|
| Wolfx | `heartbeat`（`timestamp`にepoch ms） | 60秒ごと |
| Wolfx | `pong`（こちらの `ping` への応答） | 送った分だけ |
| P2P | 地震情報と、不定期の各地域ピア数（code 555） | **接続から最初の555まで3分以上空くことがある** |

したがって**「p2p 受信中」は接続が生きている証明にならない**。無音を根拠に切ると
誤って繋ぎ直すので、P2P側の監視は10分と緩くとり、代わりに最終受信時刻を画面に常時
出して判断できるようにしてある。Wolfxは毎分来るので90秒無音で切る。

Wolfxのハートビートと `pong` は epoch ms のサーバー時刻を載せている。`pong` は
自分の `ping` への応答なので往復時間が分かる。HTTPの `Date`（秒単位）より分解能が
高いので、時刻推定はこちらを主に使う（`src/clock.ts`。中央値・往復の半分を控除）。

### フィクスチャ

| ファイル | 中身 |
|---|---|
| `fixtures/history.json` | `/history` 直近50件。通常運用の姿 |
| `fixtures/quake.json` | 能登半島地震 2024/01/01 の code 551 が4件。極端な例（2829観測点・訂正あり） |
| `fixtures/wolfx_warn.json` / `wolfx_eew.json` | 予報から警報に切り替わった実データ（茨城県南部 M5.1 第12報） |

合成データは持たない。実際に流れた報をそのまま流し、変えるのは `EventID` と時刻、
そして報を重ねるために必要な値（報番号・規模・予測震度・警報かどうか・対象地域の有無）
だけ。ゴールデンテストで固定してある（`test/adapters.p2p.test.ts`, `test/store.test.ts`）。

## 実装上の判断

### 欠損センチネルはフィールドごとに独立

緯度は `-200` との**厳密比較**で判定する（`< 0` では南半球の遠地地震を落とす）。
深さ・マグニチュード・最大震度はそれぞれ独立に `-1` を判定する（遠地地震は
「震源はあるが深さだけ無い」ことがある）。`depth: 0` は「ごく浅い」であって不明ではない。

### 震度46

「5弱以上と推定されるが震度情報を入手していない」。ソート用の数値（46）と
表示ラベル（`5弱以上`）を分けて持つ（`Intensity`型）。地域別の第一報でしか出ないので、
一覧の震度バッジはこの表記だけ横に伸びる——UI側で幅を吸収してある（[一覧の見せ方](#一覧の見せ方)）。

### 同一地震のマージ

P2Pの地震情報にEventIDは無いので `earthquake.time` をキーにする。発表種別ごとに
持ち込む情報が違う（`Destination` は震源、`DetailScale` は震度）ので、置換ではなく
要素ごとにマージする。順序が逆転しても結果が変わらないことをテストで固定した。

### 区域別の震度は地図に打たない

`points` には座標が無い。観測点別（`isArea: false`）は気象庁の観測点一覧
（`JMAstations.json`）から実座標を引いて打つ。区域別（震度速報）は面であって点ではないので、
代表点を自前で作らず地図には打たない——気象庁が発表していない位置を発表内容として
描かないため。打てない点（区域別・観測点一覧に無い名前・表示範囲外）は黙って落とす。
震度そのものは詳細の一覧に出ている。

### フェイルサイレント禁止

- wolfx / p2p の接続状態を常時個別表示（未接続 / 接続中 / 受信中 / 無音 / 再接続待ち / 停止 / 異常）
- 時刻オフセットが未推定・異常ならその旨を表示
- 解析失敗の件数、履歴取得の失敗を画面に残す
- 数値が `NaN` / `Infinity` になったら表示しない（`null` を「不明」として出す）
- 報が更新されたときに古い値を持ち続けない（[報の引き直し](#報が更新されたときの引き直し)）

### 名称

このアプリ自身の出力として「緊急地震速報」「速報」を使わない。気象庁が発表した
`Title` はそのまま表示する（テストで固定）。例外は**津波の階級**で、`MajorWarning` /
`Warning` / `Watch` を**大津波警報 / 津波警報 / 津波注意報**と表示する——これは
気象庁の階級そのものの呼称であって、こちらが作った名前ではない。

## 報が更新されたときの引き直し

続報では震源も深さも規模も動く。**第1報の値を持ち続けると、画面の数字だけが古いまま残る**
——いちばん静かに嘘をつく壊れ方なので、値を覚える箇所を作らない方針にしてある。

| 表示 | 引き直しの契機 |
|---|---|
| EEWのカード（最大予測震度・震源・M・深さ・対象地域） | `eventId:serial:isCancel` が変わったら組み直す（古い／同じ報番号は store が捨てる） |
| この地点の推定震度・到達カウントダウン | 毎回計算する（記憶しない）。報の受信時と1秒ごとの再描画の両方で更新 |
| 予報円・震央のリング | 報ごとに震源要素を差し替え、半径と進み具合は毎フレーム走時表から引き直す（外挿しない） |
| 地図の震央マーカーと寄せる範囲 | 震源の緯度経度が変わったら |
| 地図の観測点 | 観測点の**全点の指紋**（名前と震度）が変わったら |

震源要素は予報円・予測震度・到達予測のいずれも0.1度・10kmに丸めて使うので、丸めの幅
より小さい移動では数字が動かない（意図した挙動）。観測点の指紋は当初「件数と先頭の1点」
だけを見ていたが、**続報で観測点の数が変わらないまま中ほどの震度だけが訂正されると
地図が古い色のまま残る**ことに気付いて全点を見るように直した。

## 画面の設計

### EEWの置き方（列にせず、地図に重ねる）

```
┌──────────────────────────────────────┬─────────┐
│ ┌───────────────┐                     │ 一覧    │
│ │[津波情報 発表中]│ ← 発表中だけ         │ 熊本…   │
│ │ 最大予測 [5−]  │                     │ 日向灘…  │
│ │ 気象庁のTitle   │                     │         │
│ │ 震源名          │      地図           │         │
│ │ M・深さ         │   （幅は変わらない）  │         │
│ │ 第N報・発表時刻  │                     │         │
│ │ [最終報][PLUM法]│                     │ 時計    │
│ │ 強い揺れ N地域  │                     │         │
│ └───────────────┘                     │         │
│  津波の判定待ち                          │         │
│  2件目以降のEEW（余震など、控えめ）        │         │
│                                        │         │
│      ┌────────────────────────┐        │         │
│      │この地点 主要動到達まで     │        │ status  │
│      │        14.0秒 [3] …      │        │         │
│      └────────────────────────┘        │         │
└──────────────────────────────────────┴─────────┘
```

**列にしない理由**: 列だと受信のたびに地図の幅が変わり、再投影で震源の位置が画面上で
飛ぶ。重ねれば地図は常に同じ大きさで、平常時は幅いっぱいを使える。列として開くのは
津波だけ（区域と高さを縦に並べるため）。

**この地点の値（到達カウントダウンと推定震度）は地図の下・中央のHUDに置く。**
カードの中に入れていたときは、全国の最大予測震度と同じ形のバッジが隣に並んで、
どちらがどこの震度か分からなかった。場所で分け、それぞれに名前を付けてある
（カード＝「最大予測」、HUD＝「この地点」）。HUDは横一列で組み、地の色は不透明
（半透明だと地形や予報円が数字に透けて読みにくい）、`pointer-events: none`
（地図クリックで現在地を指す操作を邪魔しない）。

震度の色は規格色なので、控えめにする余震カードでも**透過はかけない**（薄めると別の
階級に見える）。落とすのは文字と数字の大きさだけ。「最終報」は報番号より重い情報
なので薄い字に混ぜず印にする。取消の報では震源名を大きく出さず、この地点の枠も
付けない（無かったことになった揺れの予測は意味を持たない）。

### 対象地域の並べ方

震度別にまとめて**全件**出す（見出しは「強い揺れ」）。まとまりの中は**到達の早い順**
——気象庁の並び順（地域コード順）は探す役に立たない。気象庁が出している到達予測
時刻を添える（自前計算より確か）。時刻は**地名と別の要素**にする——文字列に足すと
時刻が地名の一部に見える。

### 主要動の到達予測（カウントダウン）

`src/lib/arrival.ts`。**予報円とまったく同じ走時表・同じ丸め・同じ補間**を通す。
別実装にすると「S円が届いているのに残り5秒」のような食い違いが出る
（`waveRadii` の逆が `travelTimes`。両者の往復が一致することをテストで固定）。

```
Δ = 震央距離（大円距離）
Ts = 走時表(丸めた深さ, Δ)
到達予測 = OriginTime + Ts
残り = 到達予測 − 補正済み現在時刻
```

- 深さで足切りしない（気象庁は150km超で主要動到達予測を行わないが、走時表は700kmまで
  値を持ち、予報円も描いている。円と数字を揃える）
- PLUM法では出さない（震源を決めていないので走時が引けない）
- 表の外（震央距離2000km超）は外挿しない

**表示は0.1秒まで出す。** 真の到達時刻とは±数秒ずれる（時刻補正±0.5秒、走時表の刻み、
そして最も大きいのは震源要素の推定誤差）が、刻みを粗くしても誤差は減らない。

**到達したら0.0秒のまま止める。** 「到達」のような文字には変えない——数字が文字に
化けると桁も幅も組み方も変わり、同じ場所の同じ値には見えなくなる。**0.0になっても
赤は解かない**（止まっている今がまさに揺れている時刻で、色が引くと「終わった」に読める）。

- 0.1秒に**切り上げる**（整数にしてから割る。`0.1`を掛けると丸め残りが出る）
- **1秒ごとの再描画では足りない**（数字が1.0ずつ飛ぶ）。カウントダウンだけが
  `requestAnimationFrame` で自分を書き替える。到達したら止める
- 整数部だけ大きく（44px）、小数部（24px）と添え字（15px）は小さく置く
- **残り10秒**から地を赤で塗る（身構えるのに要る時間から決めた。3秒では遅い）
- 状態が変わっても**枠の大きさを変えない**（幅も高さも）。実ブラウザで複数状態を
  並べて測り、位置が小数点以下まで一致することを確認してある
- P波の残り秒数は出さない（行動を決めるのは主要動。P波の到達は地図の白い円で
  分かる）。その場所は「主要動到達まで」という見出しにした

### 設定した地点の推定震度

初回起動時に現在地の設定を案内する（断れば二度と出ない。設定からいつでも開ける）。
「現在地を使う」（端末の位置情報）と「地図をクリック」の2つ。その地点のAVS30は
**設定したときに一度だけ**J-SHISから引いて端末に保存する。位置情報は端末の外に
出さない（地盤データを引くときだけ座標をJ-SHISに送る）。

計算できないときは黙って空にせず理由を出す（`PLUM法（震源なし）` / `震源が未確定` /
`規模が未確定` / `深さ150km超` / `地盤データなし`）。これは気象庁の発表ではなく
自前の計算で、誤差は±1階級が常態（気象庁自身の評価でも一致21%、±1階級以内75%）。
この断りは画面には出していない（毎回同じ文は壁紙になり、可変値の邪魔をするため）。

### 予報と警報の差、津波との重なり

警報のカードは予報より緊迫して見せる——**左端に縦の**赤白ハザードストライプ、地の色を
赤に寄せ、タイトルも赤に。横帯にしないのは、津波の帯・震度の色面と合わせて色の面が
縦に3つ積み、どれが緊急度を表しているのか読めなくなるため。津波が発表されている間は
あらゆるEEWのカードに「津波情報 発表中」を載せる（余震にも）。判定が出ていない間は
「津波 調査中」。

津波の判定待ちは確定した数字のあと（「まだ分からない」という保留の情報だから）、
余震より前（連続しても画面外に押し出されないように）。取消と進行中が混在するときは
進行中のいちばん新しいものをHUDに出す。

### 津波の見せ方

一番大きく出すのは**高さ**（30px）と**いつ来るか**（18px）。判断を決めるのはこの2つで、
区域名と階級名はその手がかりなので小さい。「直ちに来襲」「津波到達中と推測」は
時刻より強い情報なので、時刻より優先して出す。背景は気象庁の津波警報等の配色で塗る
（薄めない）。

津波の列の**最上部**に、いちばん重い階級に応じた行動を出す（大津波警報・津波警報＝
「いますぐ高台へ避難」、津波注意報＝「いますぐ海から上がる」。文言は気象庁の呼びかけに
合わせる）。**過去の発表では出さない**（`historical`）——サンドボックスの再生や
接続直後に投げ込まれた古い報で避難を促すのは、この道具が嘘をつくのと同じ。区域と
現在地の対応データを持っていないので「あなたの地域は」とは言わない。

| 階級 | 背景 | 文字 |
|---|---|---|
| 大津波警報 | 紫 `#C800FF` | 白 |
| 津波警報 | 赤 `#FF2800` | 白 |
| 津波注意報 | 黄 `#FAF500` | 黒 |

### P波・S波の予報円

`public/assets/tjma2001.txt`（気象庁JMA2001走時表、850KB）を起動時に一度だけ読み、
`src/lib/travelTime.ts` がメモリに保持する（バンドルには入れない）。半径は**地震発生
時刻からの経過秒数**で毎フレーム引き直す（発表時刻ではない。前回からの外挿もしない）。
走時表が返すのは**震央距離**（地表に沿った距離）で、そのまま円の半径にする（深さで
補正し直さない）。地図ライブラリを使っていないので、球面上の等距離点128個を投影した
多角形として描く（`src/lib/geo.ts`）。

描く／描かないの判定は `src/lib/waveCircles.ts` の1関数に閉じている。**深さでも
震源決定手法でも除外しない**——描かないのは「そもそも描けない」場合だけ。

| 条件 | 円 |
|---|---|
| 深発地震（150km超） | **描く**。走時表は700kmまで値を持つ。深いぶん出現が遅れるだけ |
| PLUM法 | **描かない**。震源を決める手法ではないので、震源から広がる波として描けない |
| 予報／警報 | どちらも描く（判定に電文種別を混ぜない） |
| 取消報 | 即座に消す |
| 走時表未読込・波が未到達・表の範囲外・震源要素なし | 描かない（0kmの円を描かない） |

EEW受信中は震央マーカーを滑らかに点滅させる（色ではなく動きで示す）。PLUM法の報では
**×印を出さない**——震源も発震時刻も決めていない手法で、震央を指す印は誤りになる
ので、「このあたりで揺れている」ことだけを示すぼんやり光る円を点滅させる。

**S波が地表に出てくるまでのリング**: 深い地震では発震から数十秒、円が1つも出ない
（深さ170kmならS波43秒）。地図に何も無いと「まだ何も起きていない」と読めるので、
震央の印のまわりにS波が地表に出るまでの進み具合をリングで出す。**見るのはS波だけ**
（被害を出すのは主要動。P波の到達はその途中の目印にすぎない。2段階にすると途中で
一度満ちて数え直すので、何が満ちようとしているのか読めなくなる）。進み具合も円の
半径も同じ走時表・同じ深さから引くので、**リングが一周した瞬間にS波の予報円が
生まれる**（一致することをテストで固定）。12時から反時計回りに、ひとつの弧が一周
ぶん伸びる。`vector-effect: non-scaling-stroke` は使わない——これを付けると破線の
刻みまで画面座標で解釈され、円周と合わなくなって全周に破片が散る。半径・線の太さ・
刻みはすべて座標系の値として渡し、倍率はJS側で掛ける。

**PLUM法の判定**は配信元の和訳文字列ではなく、**生電文`RK`の1桁目**（震央の確からしさ）
で見る（`0`不明・未定／`1-4`IPF法（点数別）／`5`防災科研／`6`海洋研究開発機構／
`7`気象研究所／`9`PLUM法）。電文を持たない配信元のために文字列（「PLUM 法」等）も
併せて見る。イベントIDごとに状態を持つので、複数のEEWが同時進行しても干渉しない。

### 一覧の見せ方

見出しは持たず、**先頭の行を大きく**して最新だと示す。**番号は振らない**——どれを
見ているかは**発震時刻**で突き合わせる（詳細の見出し `詳細 08/16 18:05` と一覧の行に
同じ時刻がある）。時刻という自然な鍵が両方に出ているので、番号は覚える手間だけを
増やしていた。

震度の箱は**行の高さいっぱい**、左端いっぱいから始める（色の帯として読ませる）。
数字を大きく（25px、先頭の行は32px）、箱は狭く（50px、先頭の行は62px）。マグニ
チュードと深さは間隔ではなく**縦線**で区切り、列幅を固定して上下の行で線の位置を
揃える。津波の有無は震源名の行の右端に日本語で出す（`Warning` では何のことか分から
ない。M・深さの欄に置くと空のときでも幅を取って間延びする）。色は階級に合わせるが
**文字色だけ**（震度の箱と色の面で競合させない）。

発震時刻は**秒まで**出す。観測点の数は一覧ではなく詳細に書く。詳細（観測点名の一覧）
は**既定で出さない**（震度の分布は地図に出ている）——設定の「表示」から出せる
（`localStorage`に覚える）。詳細を出していないあいだ、その位置には**時計**が出る
（補正済みの時刻、**JSTと明記**——このアプリの時刻表示はすべてJST固定）。**新しい
地震が来たら、そこへ移る**（古いものを手で選んでいても新着が主役になる）。

### 設定画面は素のHTML

右下の「設定」で開く画面は、**ブラウザ既定の見た目のまま**にしてある（白地・既定の
フォント・見出し・箇条書き・素のボタンとチェックボックス）。ここは平常時に開いて
読むだけの画面で、緊急時の視認性とは関係が無い。作り込むと直すたびに本体の計器と
二重に手が要る。受信状態は色の丸ではなく**文字**で言う（`wolfx 受信中（最終受信
19:00:05）`）。アプリ側の指定（暗色・独自フォント等）を `revert` で打ち消し、
`color-scheme: light` も明示する（`:root`が`dark`のままだとボタンもOSの暗色版に
なる）。残した装飾は太字だけ（時刻ずれ異常・劣化理由）。

### 項目の並べ方・画面に文字を置く基準

複数の項目を並べるとき、**区切りに文字（「/」など）を使わない**。`display: flex`の
間隔で分ける（`src/ui/dom.ts`の`fields()`）。文字で区切ると値そのものと区切りの
見分けに一手間かかる。

画面に文字を置くかどうかは、**その文字が画面の状態によって変わるかどうか**で決める。
変わらないなら読み手が既に知っていることなので、画面ではなくこのREADMEに書く。
常時出ている説明文はゼロで、画面に残すのは値・状態・例外・押せるもののラベルだけ。

## 震度予測

`src/lib/intensityPrediction.ts`。式は気象庁「緊急地震速報検討委員会 資料2-1
（平成20年3月18日）」のもの。

| 段 | 式 | 出典 |
|---|---|---|
| 0 | `Mw = Mjma − 0.171` | 宇津(1982)・佐藤ほか(1989) |
| 1 | `log10 L = 0.5Mw − 1.85`、`X = max(R − L/2, 3)` | 宇津(2001) |
| 2 | `log10 PGV600 = 0.58Mw + 0.0038D − 1.29 − log10(X + 0.0028·10^0.5Mw) − 0.002X` | 司・翠川(1999) |
| 3 | `PGV = PGV600 × (600/AVS30)^0.66` | 松岡・翠川(1994) |
| 4 | `I = 2.68 + 1.72 log10(PGV)` | 翠川ほか(1999) |

震源要素は気象庁と同じ粒度（緯度経度0.1度・深さ10km、0kmなし）に丸める（報ごとの
微動で予測が跳ねるのを防ぐ）。**上限**は断層面までの最短距離X、**下限**は点震源の
距離R——気象庁の「震度○○から○○」はこの2つ。深さ150km超では予測しない。距離減衰式は
深さ50km以浅が対象（超えたら`beyondAttenuationDepth`）。第4段の回帰は震度4以上が対象
（下回ったら`belowRegressionRange`）。資料の計算例（Mjma 7.0／深さ20km／震央距離50km／
AVS30 250）を全桁ゴールデンテストで固定してある。

**UIに出ているのは「設定した地点」1点だけの推定**（HUDの「この地点」）。観測点
4400点ぶんの面的な計算（`predictStations` → `maxByArea`。気象庁が地域単位で最大値を
代表として発表するのと同じ集約）はテストで固定してあるが、**地図への面的な描画は
まだ繋いでいない**（見せ方が未決）。

### 観測点とAVS30

データは `public/assets/stations-avs30.json`（675KB、4416点）。

| 項目 | 出典 |
|---|---|
| コード・名称・緯度経度・所属地域 | 気象庁 震度観測点一覧（`JMAstations.json`） |
| AVS30・微地形区分・メッシュコード | 防災科研 J-SHIS 表層地盤データ V4（2020年版） |

作り直しは `python3 tools/build-avs30.py JMAstations.json public/assets/stations-avs30.json`
（4416点を1点ずつ引くので30分ほど。途中経過は`tools/.cache/`に貯まり再開できる）。

J-SHISは`position={経度},{緯度}`の順（逆にすると日本の外を指す）。ARVではなく**AVS**を
取る（ARVは工学的基盤Vs=400m/s基準で、震度予測の式（600m/s基準）と揃わない）。
**`AVS = 0`は水域**（沿岸海域・湖沼・河道）で地盤データ無しの意味——そのまま使うと
増幅率`(600/0)^0.66`が発散するので、地盤データが引けなかった地点では計算しない
（増幅なしで代用するとその地点だけ実際より小さい震度が出る）。観測点一覧の座標は
小数2桁（約1.1km）でJ-SHISの250mメッシュより粗く、海岸沿いの点が海側のメッシュに
落ちるため、124点は近傍（0.3〜0.6km）で代用した（代用した点には`fallbackKm`が入る）。

## 公開の位置づけ

このリポジトリはPublicで、コードは誰でも読める。ただし**動いているサービスは無い**
——各自がクローンしてビルドし、自分のブラウザで動かすものであって、どこかにデプロイ
された公開ページは無い。気象庁の予報業務許可制度が対象にするのは予報・警報の
**発表・伝達を反復継続して行う行為**（サイトや配信サービスとして公開・運用すること）
で、ソースを公開しておくことそのものは該当しない。

震度予測・到達予測はこの前提のもとで実装してある（気象庁の発表ではない旨・誤差の
断りは画面には出さず、この README に書いている）。**サービスとして公開する場合**は、
この位置づけごと見直すこと。

### フォントの持ち方

**CDNは使わない**（オフラインで起動することが条件）。`src/assets/`に同梱する。
欧文・数字の直立は可変フォント1本（wght 100-900、35KB）、斜体は**本物のイタリック体**
（傾き-11.3°、数字も収録、17KB）を別に持つ（斜体を持たないフォントだとブラウザが
機械的に傾けるだけで字形が崩れる）。tabular figures対応なので、時刻や座標の桁揃えを
等幅フォント無しでできる。

日本語は全グリフ4.2MBあるので、**このアプリが出す文字だけ**に絞ってある（観測点名・
市町村名・区域名・都道府県名・UIの文言＝1630文字、610KB、可変1本）。作り直しは
`python3 tools/build-jp-font.py`（要fonttoolsとbrotli）。絞った字種の外が来たら
端末のゴシックに**字ごとに**落ちる（豆腐にはならない）。

## 震度の表記

「5弱」ではなく**5と−に分けて組む**。漢字を混ぜると数字と見かけの大きさが揃わず、
一番大きく出したい値が読みにくくなるため。数字も符号も斜体で、符号はさらに小さく
少し上に置く。気象庁の正式表記（5弱）は`title`属性に残してあるので、元の表記も引ける。
